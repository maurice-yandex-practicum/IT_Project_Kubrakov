# Введение
Мы разрабатываем IT проект по каршерингу в России. Мы студенты 3 курса, поэтому размах проекта не такой же большой, как у корпорации.
В этом репозитории будут артефакты бизнес аналитика, архитектора и.т.д. Самого кода здесь не будет. Предметная область: каршеринг.
Формат диаграм draw.io.
# Артефакты
1. Основы описания предметной области
2. Диаграмма сущность-связь(нотация Чена)
3. Модель функционирования
4. Процессная модель (BPMN)
5. Архитектура ПО
6. Технический проект
7. Замысел и основные элементы программной методики испытаний 
8. Перечень аббревиатур, перечень определений, библиографические ссылки.
# Правила написания артефактов
Не упоминай перечень открытых вопросов из документа. Он только для тебя.
Не пиши информацию о том, что мы не выбрали точные контракты внешних интеграция, версии и параметры инфраструктуры.
Не пиши упоминание примера пояснительной записки.
Не пиши ИИшные противопоставления. Пример: ` Их выделение в таблице отражает разделение ответственности в коде и проектной документации, а не наличие отдельных сетевых служб или независимо развёртываемых микросервисов.`
# Откуда брать материалы
Материалы бери из гостов, названия ГОСТ, которыми ты можешь пользоваться лежат в файле `docs/gosts.md`. Ты эти госты должен гуглить и искать в них информацию. Там же будут не только, госты, но и методички.
Если хочешь взять материал не из списка, предупреждай нас об этом, пиши название материала и ссылку.
Запрет: выдумывать номера ГОСТ, пункты и цитаты.
# Структура репозитория
- docs/gosts.md — единственный разрешённый перечень ГОСТ/методичек
- 01-domain/ — описание предметной области
- 02-er/ — ER-диаграмма (нотация Чена) + описание сущностей
- 03-functional/ — контекстная (IDEF0/Гейна-Сахсена), DFD, декомпозиция
- 04-bpmn/ — процессная модель
- 05-architecture/ — архитектура ПО
- 06-tech_project/ — технический проект(Solution)
- 07-quality/ — замысел и основные элементы программной методики испытаний 
- 99-appendix/ — глоссарий, аббревиатуры, библиография
- docs - папка с документациями только и только для ИИ агента. Упоминание этих файлов не должно попасть в артефакты.
# Про источники
Любой новый термин, источник(не относящийся к технике программной инженерии, типо "как делать BPMN") вносится в файл глоссария.
# Правила для ИИ агента
- Нам отвечай понятным языком. Файлы пиши академическим языком. Пиши только на русском, разрешается использовать английские слова, там, где это название чего-то.
- Любое допущение выноси в раздел «Открытые вопросы». Открытые вопросы пиши в `open-questions.md`.
- Если данных не хватает — задай вопрос, а не придумывай.
- Не ссылайся на ГОСТ, которого нет в docs/gosts.md.
