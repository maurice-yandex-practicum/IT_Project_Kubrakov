# Описание архитектурной диаграммы АС «Каршеринг» для ИИ-агента

## Назначение

Файл `architecture.drawio.xml` показывает логическую архитектуру автоматизированной системы «Каршеринг»: границу системы, внутренние компоненты, внешних участников, внешние системы и связи между ними. Диаграмма не фиксирует конкретные технологии и протоколы.

## Граница системы

Штриховая рамка `АС «Каршеринг» (рассматриваемая система)` включает:

- шлюз доступа к прикладным сервисам;
- сервис уведомлений;
- прикладные модули;
- подсистему интеграции с внешними системами;
- базу данных.

Внешними по отношению к рамке являются арендатор, администратор, техническая служба, системы проверки документов, телематический модуль и платёжный шлюз.

## Внутренние компоненты

### Шлюз доступа

Единая точка входа для арендатора и администратора. Шлюз передаёт запросы прикладным модулям.

### Прикладные модули

- `Модуль регистрации и управления пользователями (F1)` — оферта, документы, создание пользователя.
- `Модуль аренды ТС (F2–F5)` — поиск, начало аренды, сведения об аренде и завершение поездки.
- `Модуль состояния ТС (F6)` — приём и хранение телеметрических данных.
- `Административный модуль (F9, F10, F11)` — тарифы, парковки, просмотр штрафов и задолженностей.
- `Модуль штрафов и задолженностей (F7, F12)` — штрафы, платежи и задолженности.
- `Модуль формирования перечня ТС на обслуживание (F8)` — подготовка списка для технической службы.

### Подсистема интеграции

- `Адаптер проверки документов` взаимодействует с системой проверки паспорта и системой проверки ВУ.
- `Адаптер телематики` передаёт команды ТС и принимает телеметрию.
- `Адаптер платёжного шлюза` отправляет запросы на списание и принимает результаты оплаты.

### Инфраструктурные элементы

- `Сервис уведомлений` получает события от внутренних модулей и доставляет уведомления арендатору.
- `База данных` хранит сущности предметной области и используется прикладными модулями.

## Внешнее окружение

| Элемент | Назначение |
|---|---|
| Арендатор | Регистрация, поиск, аренда, завершение поездки и получение уведомлений |
| Администратор | Управление тарифами и парковками, начисление штрафов |
| Техническая служба | Запрос перечня ТС, требующих обслуживания |
| Система проверки паспорта | Проверка паспортных данных |
| Система проверки ВУ | Проверка водительского удостоверения |
| Телематический модуль ТС | Открытие/закрытие ТС и передача состояния |
| Платёжный шлюз | Списание оплаты и возврат результата платежа |

## Связи

- арендатор и администратор пользуются шлюзом доступа;
- шлюз передаёт запросы прикладным модулям;
- модуль регистрации вызывает адаптер проверки документов;
- адаптер документов обращается к системам проверки паспорта и ВУ;
- модуль аренды передаёт адаптеру телематики команды ТС;
- адаптер телематики передаёт состояние модулю состояния ТС;
- модуль аренды и модуль штрафов используют адаптер платежей;
- адаптер платежей отправляет запрос в платёжный шлюз и принимает результат;
- прикладные модули читают и записывают базу данных;
- прикладные модули формируют события для сервиса уведомлений;
- сервис уведомлений отправляет уведомления арендатору;
- техническая служба через шлюз запрашивает перечень ТС на обслуживание.

## Типы связей на диаграмме

- сплошная линия — синхронный запрос и ответ;
- штриховая линия — асинхронное событие или сообщение;
- штриховая рамка — граница системы.

## Правила использования агентом

1. Сохранять соответствие внутренних модулей функциям F1–F12.
2. Не превращать логические модули в отдельные микросервисы без отдельного решения проекта.
3. Не обращаться к базе данных напрямую из внешнего окружения.
4. Внешние системы подключать через соответствующие адаптеры.
5. Использовать базу данных как общий источник состояния сущностей ER-модели.
6. Считать архитектурную диаграмму логическим представлением; конкретный стек описывается в техническом проекте.

## Связь с другими моделями

- состав прикладных модулей выведен из функций функциональной модели;
- работа с данными опирается на ER-модель;
- порядок взаимодействий уточняется BPMN-моделью;
- F1–F12 являются сквозными идентификаторами для сопоставления диаграмм.
