# ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ

В настоящей пояснительной записке применяют следующие термины с соответствующими определениями:

аномалия конкурентного доступа — нарушение корректности данных, возникающее только при параллельном выполнении транзакций, каждая из которых по отдельности корректна \[1\]

архитектура (системы) — основные понятия или существенные свойства системы в окружающей среде, воплощённые в её элементах, отношениях и принципах разработки, эксплуатации и развития \[2\]

аудит — журналирование изменений данных с фиксацией типа операции, времени, пользователя и изменённых значений

веб-хук — HTTP-запрос, которым внешний сервис сообщает системе о событии, например о новом коммите в репозитории

договор — соглашение с заказчиком о выполнении проекта: номер, дата подписания, сумма и бюджет часов

ёмкость спринта — плановый объём работы команды на спринт в часах; сумма оценок задач спринта не должна её превышать

заинтересованная сторона — лицо или организация, имеющие интерес в системе или в её характеристиках \[2\]

заказчик проекта — организация, для которой выполняется проект; с системой не работает, требования передаёт руководителю проекта, отчёты получает по почте

ключ задачи — идентификатор задачи вида «код проекта — номер задачи», например SHOP-42; по нему коммиты и уведомления связываются с задачей

коррелированный подзапрос — подзапрос, условие которого ссылается на столбцы текущей строки внешнего запроса и который поэтому вычисляется для каждой такой строки

лингвистический минимум — минимальный набор понятий (сущностей, атрибутов, связей), достаточный для описания предметной области и функций системы

материализованное представление — представление, результат которого хранится в базе и обновляется по команде, а не вычисляется при каждом обращении

миграция — сценарий изменения структуры существующей базы данных, сохраняющий ранее накопленные данные

пакетная загрузка — загрузка набора записей из файла с предварительной проверкой каждой записи и отчётом об отклонённых

проект — временное предприятие, направленное на создание уникального продукта, услуги или результата \[3\]

скорость команды — сумма оценок задач, выполненных командой за спринт, ч

слабая сущность — сущность, экземпляры которой идентифицируются только вместе с экземпляром определяющей сущности

спринт — итерация проекта фиксированной длительности (две недели), на которую планируется часть задач

транзакция — последовательность операций с базой данных, выполняемая как единое целое: фиксируются все изменения или ни одного

триггер — функция, которую СУБД автоматически вызывает при вставке, изменении или удалении строк таблицы

уровень изоляции — степень, в которой транзакция видит изменения параллельных транзакций (READ COMMITTED, REPEATABLE READ, SERIALIZABLE)

элемент среды окружения — внешняя по отношению к системе сущность — человек, организация или другая система, — взаимодействующая с ней непосредственно или через другие элементы окружения

# ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ

В настоящей пояснительной записке применяют следующие сокращения и обозначения:

3НФ — третья нормальная форма

БД — база данных

ИР — информационный ресурс

ПО — программное обеспечение

ПР — принципы развития

ПФ — принципы функционирования

СУБД — система управления базами данных

ТН — требование назначения

ТТ — техническое требование

ФТ — функциональное требование

ФТТ — функционально-техническое требование

ЭСО — элемент среды окружения

BPMN — Business Process Model and Notation, нотация моделирования бизнес-процессов

CSV — Comma-Separated Values, текстовый формат табличных данных

CTE — Common Table Expression, обобщённое табличное выражение

DFD — Data Flow Diagram, диаграмма потоков данных

ER — Entity–Relationship, модель «сущность — связь»

FK — Foreign Key, внешний ключ

MVCC — Multiversion Concurrency Control, многоверсионное управление параллельным доступом

PK — Primary Key, первичный ключ

SQL — Structured Query Language, язык структурированных запросов

SSO — Single Sign-On, технология единого входа
