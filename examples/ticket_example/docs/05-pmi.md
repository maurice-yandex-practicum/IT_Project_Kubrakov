- **Объект** — комплекс программ «Продажа билетов и контроль входа на мероприятия» (`RU.XXXXXXXX.00001-01`; документ — `RU.XXXXXXXX.00001-01 51 01`): приложение K1–K11, БД PostgreSQL с ограничениями, функциями и триггерами, эксплуатационная документация. Эмулятор банка — средство, а не объект.

## 5.7. Показатели и критерий качества

Дерево «удовлетворённость пользователя ← критерии ← показатели»: частные критерии определяют степень удовлетворённости каждой функцией, интегральный — качество продукта. Показатели x ∈ [0; 1] считаются по проверкам §5.6; каждая проверка входит в показатель (кроме Н-03 — исследование индексов). Инвариант в правиле критерия — множитель: его нарушение обнуляет критерий. Числа — предложение, уточняются с заказчиком.

**Q = Σ wᵢ·Kᵢ + Σ wⱼ·x0.ⱼ**, Σ w = 1.

**Критерий приёмки.** Система принимается, только если выполнены все три условия:
1. пройдены **обязательные проверки** — провал любой из них означает отказ в приёмке при любом Q:
   - двойная продажа — Б-01, К-01, К-02;
   - повторный проход — Б-04, К-03;
   - списание и выдача билетов — Ф-06, Ф-18, Ф-20, Ф-21;
   - полный откат отмены мероприятия — С-02;
   - возвраты после сбоя банка — В-04;
   - актуальность отчёта — Ф-11;
   - время ответа — Н-01, Н-02;
2. выполнены условия назначения: x2.2 = 1, x5.2 = 1, K1, K2, K3, K5, K6 ≥ 0,9;
3. Q ≥ 0,9.

Высокий Q не компенсирует провал обязательной проверки: например, бронь за 375 мс при нормативе 300 мс (Н-01) или повторный перевод при сбое банка (В-04) — «не принято».

**Отчётность** (ГОСТ 34.603-92, пп. 3.2, 4.9): протоколы (проверки, факт, недостатки, x, K, Q, решение), журнал опытной эксплуатации, акты приёмки.
