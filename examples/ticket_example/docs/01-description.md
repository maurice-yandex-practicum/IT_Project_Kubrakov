# 1. Описание предметной области и процесса

*Стадия «Исследование и обоснование разработки» (ГОСТ 34.601-90, стадии 1–2; ГОСТ Р 57193-2025, п. 6.4.1).*

## 1.1. Система, программный продукт, назначение

- **Система** — продажа билетов и контроль входа на мероприятия: участники (организатор, покупатели, контролёры, администратор сервиса, платёжный сервис), их процесс (§1.4) и комплекс программ.
- **Программный продукт** — комплекс программ «Продажа билетов и контроль входа»: ведёт мероприятия, места, заказы, оплаты, возвраты и проходы и не даёт нарушить правила процесса (§1.6).
- **Назначение** — обеспечить продажу мест на мероприятия так, чтобы одно место одновременно занимала не более чем одна действующая бронь или один действительный билет, покупатель получал билет или понятный отказ, на мероприятие проходили только по действительному билету, а организатор сам выставлял мероприятие на продажу и видел продажи, возвраты и посещаемость на момент запроса.

Таблица: Части назначения и проблемы, которые они снимают

| Часть назначения | Для кого | Какую проблему §1.2 снимает |
|---|---|---|
| Н1 — одно место одновременно занимает не более одной действующей брони или действительного билета (после возврата место снова продаётся) | покупатель, организатор | двойная продажа при одновременной покупке |
| Н2 — покупатель получает билет или понятный отказ | покупатель | «деньги ушли, билета нет», непонятный возврат |
| Н3 — проходят только по действительному билету | контролёр, организатор | поддельный, возвращённый или уже использованный билет |
| Н4 — организатор сам выставляет мероприятие на продажу и видит продажи, возвраты, посещаемость на момент запроса | организатор | нет данных в реальном времени, ручной возврат при отмене |

## 1.2. Проблема и противоречие

Таблица: Проблемы участников без системы

| Участник | Проблема без системы |
|---|---|
| Покупатель | одно место продаётся дважды; непонятно, сколько вернут при отказе |
| Организатор | не знает в реальном времени, сколько продано и сколько пришло; отмена — ручной возврат по каждому билету |
| Контролёр | не может проверить, что билет не поддельный, не возвращён и не использован на другом входе |
| Администратор | схемы залов вводятся вручную, дубли мест всплывают при продаже |

**Противоречие организатора:** продать больше и быстрее и дать покупателю удобство (выбрать места, подумать, вернуть) — и при этом не продать место дважды, не держать места без оплаты и не потерять деньги. Чем жертвуем, чтобы снять противоречие:

Таблица: Решения противоречия организатора и их цена

| Решение | Чем жертвуем |
|---|---|
| бронь держит места 15 минут, потом снимается (R02) | покупатель должен оплатить быстро |
| двухстадийная оплата: билеты — только после списания денег (R22) | несколько секунд ожидания билета |
| возврат по сроку до начала: 100 / 50 / 30 % (R16) | часть денег покупателя при позднем возврате — организатор успевает перепродать места |
| проверка билета на входе по БД, а не по бумаге (R13, R14) | на входе нужен доступ к системе |

## 1.3. Концепция качества

- **Качество** — степень, в которой продукт удовлетворяет пользователей (покупателя, организатора, контролёра): достигает назначения Н1–Н4 и при этом надёжен, защищён и удобен (ГОСТ Р ИСО/МЭК 25010-2015).
- **Как измеряется:** показатели x ∈ [0; 1] считаются по результатам проверок ПМИ → частный критерий Kᵢ на каждую функцию (степень удовлетворённости функцией; инвариант — множителем) → интегральный критерий Q = Σ wᵢ·Kᵢ + Σ wⱼ·x0.ⱼ (§5.7). Модель качества — верхняя часть ER (§2.2).
- **Критерий достижения качества (приёмки):** Q ≥ 0,9 **и** x2.2 = 1 (нет двойной продажи) **и** x5.2 = 1 (нет повторного прохода) **и** K1, K2, K3, K5, K6 ≥ 0,9 **и** пройдены все обязательные проверки (§5.7): провал любой из них — отказ в приёмке при любом Q.
- **Как убеждаем заказчика:** приёмочные испытания по ПМИ (§5) — внешняя верификация; опытная эксплуатация и практика — валидация.
- **Контролепригодность** (FR-28): пользователь видит, как получен результат, — в брони цена и скидка каждого билета; в отказе — причина; в уведомлении о возврате — расчёт по R16; на входе — имя держателя или причина отказа; в отчёте — сверка «выручка = Σ списанных платежей − Σ возвратов».

## 1.4. Участники и процесс

Таблица: Участники процесса

| Участник | Что ему нужно | Что получает от системы |
|---|---|---|
| Покупатель (любой зарегистрированный пользователь) | купить места; вернуть билет | бронь или отказ с причиной; билеты с кодом; уведомление о возврате |
| Организатор (менеджер юрлица) | выставить мероприятие на продажу; знать результаты | подтверждение публикации и ролей; отчёт о продажах и посещаемости |
| Контролёр (сотрудник организатора) | пропустить только по действительному билету | «проход разрешён» или причина отказа |
| Администратор сервиса | поддерживать площадки и схемы залов | протокол загрузки схемы; регистрация организатора |
| Платёжный сервис (внешняя система) | — | счёт, решение о списании, распоряжение на возврат |

**Процесс** (ГОСТ Р 57098-2023, п. 5.3) «Продажа билетов и контроль входа»; **цель** — место занято не более чем одним действительным билетом, деньги и билеты соответствуют друг другу, проходят только по действительным билетам; **результаты** — мероприятие опубликовано; места удержаны или дан отказ; оплаченный заказ стал билетами, неоплаченная бронь снята; возврат по правилам; один проход на билет; организатор видит итоги.

## 1.6. Правила

Из правил выводятся сущности, связи и ограничения (ER, §2.2) и требования (§2.1).

Таблица: Правила предметной области

| Код | Правило |
|---|---|
| R01 | Место на мероприятии занято не более чем одной действующей бронью или проданным билетом. |
| R02 | Бронь держит места 15 минут; неоплаченная бронь снимается, места освобождаются. |
| R03 | Бронировать можно только опубликованное мероприятие внутри окна продаж. |
| R04 | Нельзя продать билет на отменённое или прошедшее мероприятие. |
| R05 | Продаётся только зона, открытая на мероприятие, по цене этого мероприятия. |
| R06 | Место принадлежит зоне билета, зона — залу площадки мероприятия. |
| R07 | Заказ: бронь → оплачивается → оплачен; «оплачивается → бронь», если сумма не списалась; бронь → истёк (по сроку); бронь → отменён. Заказ «оплачивается» по сроку не снимается: место держится до ответа банка. |
| R08 | Цена и скидка фиксируются в каждом билете при оформлении; сумма к оплате = Σ (цена − скидка) и больше нуля. |
| R09 | Промокод действует в свой срок и не больше лимита применений. |
| R10 | Платёж с одним ID транзакции сервиса учитывается один раз. |
| R11 | Билет действителен только по оплаченному заказу. |
| R12 | Код доступа билета уникален. |
| R13 | По билету не более одного успешного прохода. |
| R14 | Проход — только на мероприятие, которое контролёр обслуживает, на входе площадки мероприятия, в окне входа. |
| R15 | Не более одного возврата на билет; использованный билет не возвращается. |
| R16 | Возврат от оплаченной стоимости (цена − скидка): ≥ 10 суток до начала — 100 %, 5–10 — 50 %, 3–5 — 30 %, < 3 — нет; при отмене — 100 % (ст. 52.1 Основ законодательства о культуре). |
| R17 | Отмена мероприятия одной операцией возвращает все билеты, снимает брони и формирует распоряжения на возврат; они повторяются до подтверждения. |
| R18 | Изменения заказов, билетов и цен пишутся в журнал: кто, когда, что было и стало. |
| R19 | Организатор видит только свои мероприятия; контролёр — только мероприятия своего организатора. |
| R20 | Схема зала загружается целиком; строка с ошибкой — в протокол; повтор места в зоне недопустим. |
| R21 | Промокод действует только на мероприятия выпустившего его организатора. |
| R22 | Оплата двухстадийная: сумма блокируется, списывается по решению системы; билеты — только после «списано»; результат после истечения брони или «не списано» — блокировка снимается, платёж «отменён»; если ответ банка задерживается, исход списания уточняется у сервиса по ID платежа, повтор ответа не создаёт второй платёж и второй комплект билетов. |
| R23 | Возврат — по платежу заказа; сумма возвратов не больше суммы платежа. |

## 1.7. Границы системы

Внутри — учёт пользователей и ролей, каталог, бронирование, оплата, возвраты, контроль входа, отчётность, журнал. Снаружи — платёжный сервис (эмулятор) и сканер контролёра. Вне объёма (развитие, §3.5) — бесплатные (пригласительные) билеты, перепродажа, лист ожидания, динамические цены, выплаты организаторам, рассылки. Вход в систему (email и пароль → токен) — техническая функция шлюза.
