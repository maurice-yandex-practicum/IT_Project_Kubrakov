# Техническое задание на систему (краткое; электронное приложение к записке)

*Структура — по ГОСТ 34.602-89 (его прислал преподаватель; действующая редакция — ГОСТ 34.602-2020). По п. 2.2 стандарта разделы, не относящиеся к учебной системе (транспортабельность, метрология, ЗИП и т. п.), исключены. Содержание не повторяется: каждый пункт ссылается на раздел записки, где требование раскрыто.*

## 1. Общие сведения

- **Наименование системы:** «Система продажи билетов и контроля входа на мероприятия».
- **Основание:** учебный план 5 семестра МАИ, дисциплины «Практикум IT-разработки» и «Базы данных» (курсовая работа).
- **Заказчик:** преподаватель дисциплины «Практикум IT-разработки». **Разработчики:** студенты группы М8О-303БВ-24 Афромеев И. А., Сылкин И. Р.
- **Сроки:** начало — ноябрь 2026 года; показ черновика стадий 1–5 — 13.11.2026; окончание — по графику курса.
- **Результаты предъявляются:** пояснительной запиской по ГОСТ 7.32-2017 и демонстрацией прототипа.

## 2. Назначение и цели создания системы

- **Назначение:** продажа билетов на мероприятия с бронированием мест, двухстадийной оплатой, возвратами по закону и контролем входа по коду билета; отчёты организаторам (раздел 1).
- **Цели (проверяемые):**
  - одно место мероприятия не продаётся дважды, в том числе при одновременных заявках (R01, NFR-03);
  - бронь держит места 15 минут; деньги списываются, только если бронь жива (R02, R22);
  - возврат считается по сроку до начала мероприятия, отмена мероприятия возвращает 100 % (R16, R17);
  - проход по одному билету возможен ровно один раз (R13);
  - критерий приёмки — как в ПМИ (§5.7): пройдены обязательные проверки (двойная продажа, повторный проход, списание и билеты, откат отмены, возвраты после сбоя, актуальность отчёта, время ответа), выполнены условия назначения (x2.2 = 1, x5.2 = 1, K1, K2, K3, K5, K6 ≥ 0,9) и Q ≥ 0,9; провал обязательной проверки — отказ при любом Q.

## 3. Характеристика объекта автоматизации

Участники, процесс, сценарии S1–S9, правила R01–R23 и словарь — раздел 1. Система, её пользователи и оценка качества — декларативная модель (§2.2): одна ER-диаграмма с предметной областью и системой оценивания качества.

## 4. Требования к системе

- **К системе в целом:**
  - структура — модульный монолит из компонентов K1–K11 и четырёх групп данных (раздел 3);
  - показатели назначения, надёжность, безопасность — NFR-01…NFR-08 (§2.1);
  - перспективы развития и модернизации — принципы развития ПР-1…ПР-8 (раздел 3).
- **К функциям:** функции F1–F6 и требования FR-01…FR-28 (§2.1); документы, обращения к хранилищам и порядок работы — модель функционирования и процессы BPMN (§2.3, §2.4).
- **К видам обеспечения:**
  - информационное — ER (§2.2), физическая схема в PostgreSQL 17, 3НФ, журнал изменений (§4.4);
  - программное — Python 3.12, FastAPI, Pydantic 2, Psycopg 3, APScheduler (§4.1);
  - техническое — развёртывание в Docker Compose (§4.4);
  - лингвистическое — интерфейс на русском языке, обмен по REST/JSON (§4.4).
