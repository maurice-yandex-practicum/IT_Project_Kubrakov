# 8. Перечень сокращений, терминов и источников

## 8.1. Сокращения

- АС — автоматизированная система; БД — база данных; ТС — транспортное средство; ТО — техническое обслуживание; ВУ — водительское удостоверение; ПТС — паспорт транспортного средства.
- API — программный интерфейс; REST — стиль организации интерфейса; HTTP/HTTPS — протокол обмена и его защищённый вариант; JSON — формат сообщений; JWT — токен доступа.
- BPMN — нотация процессной модели; DFD — диаграмма потоков данных; ER — модель «сущность — связь»; UUID — уникальный идентификатор; SMTP — протокол передачи почты.
- P95 — 95-й процентиль измеренного набора; RAM — оперативная память; vCPU — виртуальный процессор; UTC — всемирное координированное время; ПМИ — программа и методика испытаний.
- C4 — модель описания архитектуры на уровнях программной системы, контейнеров, компонентов и кода.

## 8.2. Термины

**Контейнер C4** — приложение или хранилище данных, составляющее часть программной системы. В проекте выделены серверное приложение и база данных. **Компонент C4** — часть одного контейнера с определённой ответственностью и интерфейсами взаимодействия.

**Каршеринг** — сервис краткосрочной аренды ТС без экипажа. В проекте рассматривается серверная автоматизация регистрации, аренды, расчётов и состояния парка.

**Аренда** — предметная запись связи арендатора, ТС и тарифа: попытка начала, время начала и окончания, применённые условия стоимости, итог и финансовый результат. Состояния: оформляется, действует, неуспешное начало, завершена.

**Оферта** — предложение оператора заключить договор аренды с изложенными условиями. Принятие оферты арендатором при регистрации означает заключение договора в электронной форме; факт и дата принятия сохраняются у пользователя.

**Арендатор** — зарегистрированный пользователь, допущенный к операциям сервиса по установленным правилам.

**Попытка начала аренды** — запись starting с закреплённым ТС и согласованными условиями; до подтверждения открытия оплачиваемое время не идёт.

**Операционный статус ТС** — available, reserved, rented или blocked, определяемые правилами аренды. **Технический признак** — normal, service_required или unavailable, получаемые по телеметрии.

**Снимок финансовых условий** — сохранённые в аренде стартовая стоимость, единица времени и цена, применяемые независимо от последующих изменений справочника.

**Тариф** — минутная единица времени, цена единицы и признак активности. Стартовая стоимость модели сохраняется вместе с условиями аренды.

**Телематический модуль** — внешнее по отношению к серверному ПО средство приёма команд и передачи состояния; в проектных проверках используется имитатор. Запуск двигателя и диагностика не моделируются.

**Поколение команды (lease_version)** — монотонный номер закрепления ТС за попыткой; позволяет отклонить старую команду при новом закреплении. **Последовательность команды (command_seq)** — порядок открытия и закрытия внутри поколения; закрытое поколение не открывается задержанной командой.

**Ключ идемпотентности** — идентификатор повторяемого запроса с сохранёнными параметрами, по которому повтор возвращает прежний результат.

**Платёжная попытка** — техническая запись исполнения оплаты конкретного обязательства с внутренним и внешним идентификаторами и статусом pending/paid/failed. **Обязательство** — сумма штрафа или задолженности с состоянием unpaid/paid; следующая платёжная попытка не создаёт новое обязательство.

**ЮKassa** — выбранная внешняя платёжная система. **Тестовый магазин** — предоставленный провайдером режим интеграционных проверок с тестовыми средствами оплаты. **Уведомление платежа** — сигнал о состоянии внешнего объекта, проверяемый получением текущего объекта по API.

**Исходящее задание** — сохранённое вместе с предметным изменением действие для внешней системы. **Аренда задания** — ограниченное время владения записью обработчиком, после истечения которого допускается безопасное продолжение.

**Квитанция сообщения** — сохранённая связь message_id, отпечатка содержимого и исхода обработки.

**Регламент ТО** — выбранные для проекта интервалы модели и пороги, применяемые к состоянию и сведениям последнего обслуживания. Это параметры проекта; заводские нормативы ими не объявляются.

**Требование** — утверждение с идентификатором, основанием, условием и ожидаемым результатом. **Критерий** — правило сравнения наблюдения с требованием. **Проверка** — сценарий с исходными данными, эталоном и способом наблюдения. **Выполнение проверки** — запись фактического прогона определённой версии.

**Свидетельство** — ответ API, состояние данных, сообщение, журнал, временная отметка либо зафиксированный результат задачи участника. **Покрытие** — наличие подготовленной проверки требования. **Результат использования** — выполнение задачи участником и правильность интерпретации полученных сведений.
