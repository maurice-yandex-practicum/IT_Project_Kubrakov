# Описание функциональной диаграммы АС «Каршеринг» для ИИ-агента

## Назначение

Файл `func_model.drawio(2)(3).xml` содержит функциональную модель в нотации Гейна—Сарсона: контекстную диаграмму, DFD уровня 1, DFD уровня 2, DFD уровня 3 и диаграмму декомпозиции функций. Модель показывает функции системы, внешних участников, хранилища и потоки данных.

## Контекстная модель

Контекстная функция — `Каршеринг (F0)`. Внешние участники и системы:

- арендатор;
- администратор;
- техническая служба;
- платёжный шлюз;
- система проверки паспорта;
- система проверки ВУ;
- телематический модуль.

Основные входные потоки: запрос на регистрацию, запрос на поиск ближайших ТС, запрос на аренду, запрос на завершение аренды, параметры тарифа, параметры парковки, запрос на штраф, запросы на просмотр задолженностей и запросы внешних систем.

Основные выходные потоки: статус регистрации, ближайшие ТС, подтверждение аренды, результат завершения аренды, состояние ТС, команда открытия/закрытия, результат списания, ссылка на списание, штраф, перечень ТС на обслуживание, результат изменения, уведомления о штрафах и задолженностях.

## DFD уровня 1

На первом уровне функции F1–F12 раскрыты как отдельные процессы.

| Код | Процесс | Основные хранилища и интеграции |
|---|---|---|
| F1 | Регистрация пользователя | БД пользователей, паспорт, ВУ, системы проверки документов |
| F2 | Поиск ближайших ТС | БД ТС и данные состояния |
| F3 | Арендовать ТС | БД ТС, аренды, тарифов, моделей, пользователи, задолженности, телематика |
| F4 | Получить информацию об аренде ТС | БД аренды, моделей и тарифов |
| F5 | Завершить аренду | БД аренды, состояния, ТС, парковок, задолженностей, телематика, платёжный шлюз |
| F6 | Обновить состояние ТС | Телематический модуль и БД состояний |
| F7 | Начислить штраф | Администратор, БД штрафов, платёжный шлюз, арендатор |
| F8 | Формирование перечня ТС | Техническая служба, БД состояний |
| F9 | Управление тарифами | Администратор и БД тарифов |
| F10 | Управление парковкой | Администратор и БД парковок |
| F11 | Просмотр штрафов и задолженностей | Арендатор/администратор, БД штрафов и задолженностей |
| F12 | Оплата штрафов и задолженностей | Платёжный шлюз, БД штрафов, задолженностей и состояний |

## DFD уровня 2

Уровень 2 детализирует два основных сценария.

### Регистрация и аренда

- подтверждение оферты;
- проверка документов;
- создание пользователя;
- проверка состояния выбранного ТС;
- проверка задолженности пользователя;
- получение тарифа и стартовой стоимости;
- создание записи аренды;
- разблокировка ТС;
- возврат подтверждения аренды.

### Завершение аренды

- получение идентификатора ТС по аренде;
- получение времени аренды, тарифа и стартовой стоимости;
- получение местоположения;
- подтверждение парковочного места;
- расчёт итоговой стоимости;
- запрос списания;
- закрытие ТС;
- завершение аренды;
- создание задолженности при неуспешной оплате.

## DFD уровня 3

Уровень 3 уточняет обмены внутри проверки документов и получения тарифа:

- паспорт и ВУ передаются соответствующим системам проверки;
- результаты проверок возвращаются функции проверки документов;
- функция создания пользователя и функция создания аренды используют результаты проверок;
- функция получения тарифа читает модель, стартовую стоимость и параметры тарифа.

## Декомпозиция функций

Отдельный лист «Декомпозиция функций» показывает иерархию функций без потоков данных. Линии на этом листе означают подчинённость функции, а не передачу данных.

Верхний уровень — `Каршеринг (F0)`. Он раскрывается в функции F1–F12. Функции F1, F3 и F5 раскрыты до подфункций, которые уже используются в DFD:

- F1: F1.1 Подтвердить оферту, F1.2 Создать пользователя, F1.3 Проверить документы;
- F3: F3.1 Проверить состояние ТС, F3.2 Проверить задолженности пользователя, F3.3 Создать запись аренды, F3.4 Разблокировка ТС, F3.5 Получить тариф и стартовую стоимость;
- F5: F5.1 Получение идентификатора ТС, F5.2 Подтвердить парковочное место, F5.3 Рассчитать итоговую стоимость, F5.4 Закрыть ТС, F5.5 Завершить аренду.

Функция F3 дополнительно использует подфункцию F1.3 «Проверить документы». Отдельная подфункция F3 для проверки документов не вводится: на диаграмме повторное использование показано штриховой стрелкой «использует F1.3».

Остальные функции F2, F4, F6–F12 на этом уровне не декомпозируются. Состав подфункций совпадает с DFD уровня 2 и уровня 3; коды подфункций используются для прослеживаемости между листами.

## Правила чтения потоков

1. Стрелка от внешнего участника к процессу — входной запрос или команда.
2. Стрелка от процесса к внешнему участнику — результат операции, уведомление или ссылка на оплату.
3. Поток между процессом и БД означает чтение либо запись данных.
4. Потоки телематики содержат идентификатор ТС, состояние и местоположение.
5. Потоки платежей должны связываться с конкретной арендой, штрафом или задолженностью.
6. Один и тот же участник на разных страницах может быть показан повторно для локальной читаемости диаграммы.

## Прослеживаемость

- F1–F5 образуют основной пользовательский сценарий регистрации и аренды.
- F6 поставляет данные состояния для F2, F3, F5 и F8.
- F7 и F12 обслуживают финансовые обязательства.
- F9 и F10 предоставляют администратору справочные параметры.
- F11 предоставляет сведения о штрафах и задолженностях.
- Диаграмма декомпозиции функций показывает иерархию F0 → F1–F12 → подфункции F1, F3 и F5.
- BPMN описывает последовательность операций, а архитектура группирует эти функции по модулям.
