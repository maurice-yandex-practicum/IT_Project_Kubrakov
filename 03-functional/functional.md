# Функциональная модель АС «Каршеринг»

## 1. Назначение модели

Файл `func_model.drawio(2)(3).xml` содержит модель функционирования в нотации Гейна—Сарсона: контекстную диаграмму, DFD уровня 1, уточняющие фрагменты уровня 2 и 3, диаграмму декомпозиции функций и лист уточнённых потоков. Модель показывает функции системы, внешних участников, хранилища и потоки данных.

Функциональная модель описывает преобразование данных, а не программные компоненты. Программные исполнители закрепляются за операциями процессов в BPMN-модели и затем обобщаются в архитектуре.

## 2. Контекстная модель

Контекстная функция — `Каршеринг (F0)`. Внешние участники и системы:

- арендатор;
- администратор;
- техническая служба;
- платёжный шлюз;
- система проверки паспорта;
- система проверки ВУ;
- телематический модуль.

Основные входные потоки: запрос на регистрацию, запрос на поиск ближайших ТС, запрос на аренду, запрос на завершение аренды, параметры тарифа, параметры парковки, запрос на штраф, запросы на просмотр обязательств, телематические сообщения и результаты платежей.

Основные выходные потоки: статус регистрации, ближайшие ТС, подтверждение аренды, результат завершения аренды, состояние ТС, команда открытия и закрытия, результат списания, ссылка на списание, штраф, перечень ТС на обслуживание, результат изменения, уведомления о штрафах и задолженностях.

## 3. DFD уровня 1

На первом уровне функции F1–F12 раскрыты как отдельные процессы.

| Код | Процесс | Основные хранилища и интеграции |
|---|---|---|
| F1 | Регистрация пользователя | Пользователи, паспорт, ВУ, системы проверки документов |
| F2 | Поиск ближайших ТС | ТС, состояние |
| F3 | Арендовать ТС | ТС, состояние, аренды, тарифы, модели, пользователи, задолженности, телематика |
| F4 | Получить информацию об аренде ТС | Аренды, модели, тарифы, состояние |
| F5 | Завершить аренду | Аренды, состояние, ТС, парковки, задолженности, телематика, платёжный шлюз |
| F6 | Обновить состояние ТС | Телематический модуль и состояние |
| F7 | Начислить штраф | Администратор, штрафы, платёжный шлюз, арендатор |
| F8 | Формирование перечня ТС | Техническая служба, состояние, ТС |
| F9 | Управление тарифами | Администратор и тарифы |
| F10 | Управление парковкой | Администратор и парковки |
| F11 | Просмотр штрафов и задолженностей | Арендатор, администратор, штрафы, задолженности |
| F12 | Обработка результатов оплаты | Платёжный шлюз, аренды, штрафы, задолженности |

## 4. Описание функций

Для каждой функции указаны назначение, инициатор, входы, используемые сведения, изменяемые данные, результат и ошибочные исходы.

### F1. Регистрация пользователя

Назначение — создать пользователя, допущенного к сервису. Инициатор — арендатор. Входы — сведения пользователя, паспорт, ВУ, решение по оферте. Используемые сведения — результаты проверки документов. Изменяемые данные — запись пользователя, паспорт и ВУ со статусами. Результат — подтверждение регистрации или отказ; получатель — арендатор. Ошибочные исходы — непринятая оферта, отрицательная проверка паспорта или ВУ, недоступность внешней системы.

### F2. Поиск ближайших ТС

Назначение — предоставить перечень доступных ТС рядом с точкой поиска. Инициатор — арендатор. Входы — координаты точки поиска и радиус. Используемые сведения — карточки ТС, операционный статус, актуальное местоположение из состояния. Изменяемые данные — отсутствуют. Результат — упорядоченный по расстоянию перечень ТС; получатель — арендатор. Ошибочные исходы — отсутствие подходящих ТС (пустой перечень), некорректные координаты.

### F3. Арендовать ТС

Назначение — начать аренду выбранного ТС. Инициатор — арендатор. Входы — идентификатор ТС, сведения пользователя. Используемые сведения — доступность ТС, задолженность, результаты повторной проверки документов, применимый тариф, стартовая стоимость модели. Изменяемые данные — запись аренды, состояние ТС, результат команды разблокировки. Результат — подтверждённое начало аренды, состояние ожидания или отказ; получатель — арендатор. Ошибочные исходы — ТС недоступно, есть задолженность, документы недействительны, разблокировка не подтверждена.

### F4. Получить информацию об аренде ТС

Назначение — предоставить арендатору сведения о его аренде. Инициатор — арендатор. Входы — идентификатор аренды. Используемые сведения — аренда, ТС, модель, состояние, применённые условия стоимости. Изменяемые данные — отсутствуют. Результат — сведения об аренде и предварительная стоимость; получатель — арендатор. Ошибочные исходы — аренда не найдена, аренда принадлежит другому пользователю.

### F5. Завершить аренду

Назначение — завершить аренду и определить финансовый результат. Инициатор — арендатор. Входы — идентификатор аренды. Используемые сведения — аренда, местоположение ТС, парковки, применённые условия стоимости. Изменяемые данные — время окончания, итоговая стоимость, состояние ТС, обязательство, результат команды закрытия. Результат — операционный и финансовый результат; получатель — арендатор. Ошибочные исходы — аренда не найдена, парковка не подтверждена, закрытие ТС не подтверждено, платёж ожидает подтверждения или завершился отказом.

### F6. Обновить состояние ТС

Назначение — поддерживать актуальное состояние ТС. Инициатор — телематический модуль. Входы — телематическое сообщение. Используемые сведения — карточка ТС, предыдущее состояние. Изменяемые данные — актуальное состояние. Результат — подтверждение приёма или контролируемая ошибка; получатель — телематический модуль. Ошибочные исходы — некорректное сообщение, неизвестное ТС, устаревшая отметка, недоступность базы данных.

### F7. Начислить штраф

Назначение — зафиксировать штраф и предоставить ссылку на оплату. Инициатор — администратор. Входы — аренда, размер и статья штрафа. Используемые сведения — права администратора, данные аренды. Изменяемые данные — штраф, ссылка на оплату. Результат — штраф и уведомление; получатель — администратор и арендатор. Ошибочные исходы — нет прав, некорректные данные, недоступность платёжного шлюза.

### F8. Формирование перечня ТС

Назначение — предоставить технической службе перечень ТС, требующих обслуживания. Инициатор — техническая служба. Входы — запрос перечня. Используемые сведения — карточки ТС, актуальное состояние, заданные критерии и нормы. Изменяемые данные — отсутствуют. Результат — перечень с основанием включения; получатель — техническая служба. Ошибочные исходы — нет прав, не заданы пороги или нормы.

### F9. Управление тарифами

Назначение — вести справочник тарифов. Инициатор — администратор. Входы — параметры тарифа. Используемые сведения — существующие тарифы. Изменяемые данные — справочник тарифов. Результат — сохранённый тариф; получатель — администратор. Ошибочные исходы — нет прав, некорректные значения.

### F10. Управление парковкой

Назначение — вести справочник парковок. Инициатор — администратор. Входы — координаты и радиус. Используемые сведения — существующие парковки. Изменяемые данные — справочник парковок. Результат — сохранённая парковка; получатель — администратор. Ошибочные исходы — нет прав, некорректные координаты.

### F11. Просмотр штрафов и задолженностей

Назначение — предоставить сведения об обязательствах с учётом роли и владельца. Инициатор — арендатор или администратор. Входы — запрос обязательств. Используемые сведения — штрафы, задолженности, принадлежность пользователю. Изменяемые данные — отсутствуют. Результат — перечень обязательств со ссылками на оплату; получатель — арендатор или администратор. Ошибочные исходы — нет прав, попытка доступа к чужим обязательствам.

### F12. Обработка результатов оплаты

Назначение — обработать результат оплаты и обновить обязательство. Инициатор — платёжный шлюз. Входы — сообщение о результате оплаты. Используемые сведения — обязательство, внешний идентификатор операции, состояние оплаты. Изменяемые данные — состояние аренды, штрафа или задолженности. Результат — подтверждение обработки; получатель — платёжный шлюз. Ошибочные исходы — неподлинное сообщение, неизвестный идентификатор, повторное сообщение, противоречивый результат.

## 5. DFD уровня 2

Уровень 2 детализирует два основных сценария.

### Регистрация и аренда

- подтверждение оферты;
- проверка документов;
- создание пользователя;
- проверка состояния выбранного ТС;
- проверка задолженности пользователя;
- получение тарифа и стартовой стоимости;
- создание записи аренды;
- разблокировка ТС;
- возврат подтверждения аренды.

### Завершение аренды

- получение идентификатора ТС по аренде;
- получение времени аренды, применённых условий стоимости и стартовой стоимости;
- получение местоположения;
- подтверждение парковочного места;
- фиксация момента окончания и расчёт итоговой стоимости;
- запрос списания;
- закрытие ТС;
- завершение аренды;
- создание задолженности при окончательной неуспешной оплате.

## 6. DFD уровня 3

Уровень 3 уточняет обмены внутри проверки документов и получения тарифа:

- паспорт и ВУ передаются соответствующим системам проверки;
- результаты проверок возвращаются функции проверки документов;
- функция создания пользователя и функция создания аренды используют результаты проверок;
- функция получения тарифа читает модель, стартовую стоимость и параметры тарифа.

## 7. Уточнённые потоки

Лист `Уточнённые потоки` фиксирует исправленные фрагменты, которые устраняют расхождения между описанием функций и прежними фрагментами диаграмм.

1. **F2.** Поток местоположения поступает из хранилища состояния; хранилище ТС даёт карточки и операционный статус.
2. **F4.** Функция читает сведения о конкретной аренде, модели, тарифе и состоянии; запись в хранилища не выполняется.
3. **F8.** Функция читает состояние ТС и карточки ТС; направление потока соответствует получению сведений, а не записи.
4. **F11.** Показаны два инициатора: арендатор запрашивает собственные обязательства, администратор — обязательства всех арендаторов; ответы различаются по составу.
5. **F12.** Показаны результаты оплаты аренды, штрафа и задолженности; обновление выполняется в соответствующих хранилищах, подтверждение возвращается платёжному шлюзу.

## 8. Декомпозиция функций

Отдельный лист «Декомпозиция функций» показывает иерархию функций без потоков данных. Линии на этом листе означают подчинённость функции, а не передачу данных.

Верхний уровень — `Каршеринг (F0)`. Он раскрывается в функции F1–F12. Функции F1, F3 и F5 раскрыты до подфункций, которые уже используются в DFD:

- F1: F1.1 Подтвердить оферту, F1.2 Создать пользователя, F1.3 Проверить документы;
- F3: F3.1 Проверить состояние ТС, F3.2 Проверить задолженности пользователя, F3.3 Создать запись аренды, F3.4 Разблокировка ТС, F3.5 Получить тариф и стартовую стоимость;
- F5: F5.1 Получение идентификатора ТС, F5.2 Подтвердить парковочное место, F5.3 Рассчитать итоговую стоимость, F5.4 Закрыть ТС, F5.5 Завершить аренду.

Функция F3 дополнительно использует подфункцию F1.3 «Проверить документы». Отдельная подфункция F3 для проверки документов не вводится: на диаграмме повторное использование показано штриховой стрелкой «использует F1.3».

Остальные функции F2, F4, F6–F12 на этом уровне не декомпозируются. Состав подфункций совпадает с DFD уровня 2 и уровня 3; коды подфункций используются для прослеживаемости между листами.

## 9. Правила чтения потоков

1. Стрелка от внешнего участника к процессу — входной запрос или команда.
2. Стрелка от процесса к внешнему участнику — результат операции, уведомление или ссылка на оплату.
3. Поток между процессом и хранилищем означает чтение либо запись данных; направление стрелки показывает направление передачи.
4. Потоки телематики содержат идентификатор ТС, состояние и местоположение.
5. Потоки платежей связываются с конкретной арендой, штрафом или задолженностью.
6. Один и тот же участник на разных листах может быть показан повторно для локальной читаемости.
7. Блок функции не является программным компонентом; исполнители операций указываются в процессной модели.

## 10. Прослеживаемость

- F1–F5 образуют основной пользовательский сценарий регистрации и аренды.
- F6 поставляет данные состояния для F2, F3, F5 и F8.
- F7, F11 и F12 обслуживают финансовые обязательства.
- F9 и F10 предоставляют администратору справочные параметры.
- F11 предоставляет сведения о штрафах и задолженностях с учётом роли.
- Диаграмма декомпозиции функций показывает иерархию F0 → F1–F12 → подфункции F1, F3 и F5.
- BPMN описывает последовательность операций и программных исполнителей, архитектура обобщает исполнителей в компоненты.

## 11. Согласованность с моделью данных

Для каждой используемой функции существуют необходимые сведения: состояние содержит местоположение и телеметрические значения; аренда хранит применённые финансовые условия; парковка содержит координаты и радиус; обязательства содержат внешний идентификатор операции, состояние и ссылку на оплату. Хранилища DFD могут объединять несколько связанных сущностей; логическое хранилище, информационный ресурс архитектуры и физическая таблица имеют разные роли в описании.
