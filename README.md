# АС «Каршеринг»

Учебный проект автоматизированной системы краткосрочной аренды автомобилей. В репозитории размещены проектные артефакты, пояснительные материалы и исходники диаграмм; программная реализация в рамках проекта не создаётся.

## Состав проектных артефактов

| № | Артефакт | Каталог | Основные файлы |
|---|---|---|---|
| 1 | Описание предметной области | `01-domain` | `domain.md` |
| 2 | Декларативная модель предметной области (ER, нотация Чена) и модель оценивания качества | `02-er` | `ERD.drawio.xml`, `ERD.png`, `er.md` |
| 3 | Модель функционирования: контекстная диаграмма, декомпозиция функций, DFD | `03-functional` | `func_model.drawio(2)(3).xml`, `functional.md`, изображения |
| 4 | Процессная модель (BPMN) | `04-bpmn` | `BPMN.drawio.xml`, `bpmn.md`, изображения |
| 5 | Архитектура программного обеспечения | `05-architecture` | `architecture.drawio.xml`, `architecture.md`, `Архитектура.png` |
| 6 | Технический проект | `06-tech_project` | `tech_project.md` |
| — | Опорный документ требований | `08-requirements` | `requirements.md` |
| 7 | Замысел и основные элементы программной методики испытаний | `07-quality` | `quality.md` |
| 8 | Перечень сокращений, терминов и источников | `99-appendix` | `appendix.md` |

## Назначение отдельных файлов

- `requirements.md` — опорный документ требований к комплекту. Он поясняет содержание технического проекта и не является отдельным сдаваемым артефактом; ссылки на него допустимы внутри проектной документации.
- `open-questions.md` — рабочий перечень решений, допущений и несогласованных мест. В состав пояснительной записки не входит.
- `quality_plan.md` в каталоге `07-quality` — служебный план подготовки артефакта 7; в состав пояснительной записки не входит.
- `architecture_diagram.md` в каталоге `05-architecture` — служебное пояснение к исходнику архитектурной схемы; в состав пояснительной записки не входит.
- Каталог `Приложения` содержит копии изображений диаграмм для вставки в пояснительную записку. Актуальными считаются изображения, повторно экспортированные из исходников `drawio` после последних изменений.

## Порядок чтения

Артефакты согласованы между собой и читаются последовательно: предметная область → декларативная модель → модель функционирования → процессная модель → архитектура → технический проект → методика испытаний. Сквозными идентификаторами служат функции `F1–F12`, имена логических компонентов и обозначения процессов `P1–P7`.

## Исходные условия проекта

Проект рассматривает серверную часть системы и её программный интерфейс. Клиентские приложения, бронирование, страхование, учёт повреждений и управленческая отчётность находятся за границами проекта. Проверка документов и телематика в испытаниях заменяются имитаторами; платёжный шлюз рассматривается как реальная внешняя система.
